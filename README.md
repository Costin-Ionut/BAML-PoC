# BAML PoC

A small project that shows how to use the key features of [BAML](https://docs.boundaryml.com/) (v0, `baml-py 0.226.2`) from Python.

Each feature lives in its own file, named after the feature (`baml_src/<feature>.baml` + `api/<feature>.py`), and is exposed as one REST route (FastAPI, served by Granian). Read one file and you see the whole feature.

## Requirements

* [uv](https://docs.astral.sh/uv/)
* Python 3.12
* An OpenAI-compatible LLM server
* VS Code + BAML extension (optional)

---

## Install

From the project folder:

```powershell
uv sync
uv run baml-cli generate
```

Without uv: `python -m venv .venv`, activate it, then `pip install -r requirements.txt` and `baml-cli generate`.

---

## Configure

```powershell
copy .env.example .env
```

Fill in `.env`:

| Key                  | Required | Where to get it                                                                                                     |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------- |
| `HOST`             | yes      | Base URL of the LLM server, ending in`/v1`                                                                        |
| `API_KEY`          | yes      | API key of the LLM server                                                                                           |
| `MODEL`            | yes      | Model name served by the LLM server                                                                                 |
| `BOUNDARY_API_KEY` | no       | Your project's API key from [Boundary Studio](https://studio.boundaryml.com/) (see [below](#boundary-studio-traces)) |
| `PORT`             | no       | Port of this API, default`8000`                                                                                   |

`config.py` loads `.env` once at startup. BAML reads the same values from the environment on every call.

## Run

```powershell
uv run main.py
```

The API starts on http://127.0.0.1:8000. Interactive docs: http://127.0.0.1:8000/docs

Run the BAML tests (defined inside the `.baml` files):

```powershell
uv run --env-file .env baml-cli test
```

## Test the routes

All routes are `POST` with a JSON body.

- **Postman:** import the ready-made collection `BAML - Tests.postman_collection.json` (**Import** -> drop the file). It has one request per route, with a working example body, and a description of each route's input and output. Start the API, then open a request and click **Send**.
- **curl:**

  ```powershell
  curl.exe -X POST http://127.0.0.1:8000/extract -H "content-type: application/json" -d '{\"text\": \"Payment page crashes since the 2.3 deploy.\"}'
  ```

## How BAML works here

```
POST /extract  ->  api/extract.py       FastAPI route
               ->  b.ExtractTicket()    generated client (baml_client/)
               ->  ExtractTicket        function + prompt (baml_src/extract.baml)
               ->  client Local         LLM settings (baml_src/clients.baml)
               ->  LLM server
               <-  BAML parses the reply into a typed Ticket, or raises an error
               <-  FastAPI returns it as JSON
```

- Only write `.baml` files and the Python routes.
- After changing any `.baml` file, run `uv run baml-cli generate` again.

## Features

### Structured output - `extract.baml`, `api/extract.py`

Turns free text into a typed object. `priority` can only be `LOW`, `MEDIUM` or `HIGH`, anything else is rejected.

```json
POST /extract
{"text": "Payment page crashes for all users since the 2.3 deploy."}

-> {"title": "Payment page crashes...", "priority": "HIGH", "tags": ["payment", "crash"]}
```

`extract.baml` also contains a BAML test (`SlowLogin`) that runs with `baml-cli test` or from the Playground.

### Streaming - `api/stream.py`

Same function, called with `b.stream.ExtractTicket`. Returns JSON Lines: one partial ticket per line, filled in as the model writes; the last line is the final ticket.

```json
POST /stream
{"text": "Typo on the About page footer."}

-> {"title": null, "priority": null, "tags": []}
  {"title": "Typo on the About page footer", "priority": "LOW", "tags": ["typo", "footer"]}
```

The status code is sent with the first line, so a reply that does not match the schema still shows `200`: the stream just ends with incomplete tickets, and the failed parse appears only as a `[BAML WARN]` entry in the server log.

### Dynamic types - `dynamic_types.baml`, `api/dynamic_types.py`

The `Category` enum is marked `@@dynamic`. The route adds the categories from the request with `TypeBuilder` just before the call.

```json
POST /classify
{"text": "My invoice charged me twice this month.", "categories": ["BILLING", "TECHNICAL", "SALES"]}

-> "BILLING"
```

### Runtime client - `api/client_registry.py`

Builds the LLM client in code with `ClientRegistry` instead of using the one in `clients.baml`. Here only `temperature` comes from the request; the same way you can switch model, key or provider.

```json
POST /client-registry
{"text": "Export to CSV is a bit slow.", "temperature": 0.2}

-> {"title": "Export to CSV is slow", "priority": "LOW", "tags": ["export", "csv"]}
```

### Token usage - `api/collector.py`

A `Collector` attached to the call records what happened. The route returns the ticket and the tokens of that call.

```json
POST /collector
{"text": "Dark mode resets after logout."}

-> {"ticket": {...}, "input_tokens": 107, "output_tokens": 173}
```

### Validation - `checks.baml`, `api/checks.py`

- `@assert` (`quantity > 0`): if it fails, the whole reply is rejected and the route returns 500.
- `@check` (`email` contains `@`): the reply always passes; the result is attached to the field.

```json
POST /checks
{"text": "Please send 3 boxes, contact me at ana@example.com"}

-> {"quantity": 3, "email": {"value": "ana@example.com", "checks": {"has_at": {"status": "succeeded", ...}}}}
```

### Tool selection - `tools.baml`, `api/tools.py`

The function returns `GetWeather | SendEmail`; the model picks one and fills in its arguments. Nothing is executed. The body field is `request`, not `text`.

```json
POST /tools
{"request": "What is the weather in Cluj?"}

-> {"tool": "get_weather", "city": "Cluj"}
```

### Retry - `clients.baml`

The `Local` client retries a failed request twice, with exponential backoff. It applies to every function; there is no separate route.

## BAML Playground (VS Code)

The Playground runs BAML functions and tests directly from VS Code, without the API.

1. Install the extension **BAML** (`Boundary.baml-extension`) from the VS Code Marketplace.
2. Open the folder in VS Code (as its own window).
3. Open any file in `baml_src/`, then click **Open Playground** above a function (or `Ctrl+Shift+P` -> **BAML Playground**).
4. Click **Settings** and set `HOST`, `API_KEY` and `MODEL`.
5. Click "run" next to a test to run it, or **Run tests below** to run all of them.

The Playground also shows the exact prompt sent to the model and the raw reply.

## Boundary Studio (traces)

[Boundary Studio](https://studio.boundaryml.com/) records every BAML call: prompt, raw reply, parsed result, latency, tokens and errors.

1. Sign up at https://studio.boundaryml.com/ and create a project.
2. Copy the project's API key.
3. Put it in `.env`: `BOUNDARY_API_KEY=...`
4. Restart the backend.

BAML sends the traces by itself when the key is set. In Studio, open **Traces**. Calls are grouped by **BAML function**, not by route: `ExtractTicket` collects the calls.

Everything sent through the API ends up in Boundary Studio.

## Troubleshooting

| Problem                                                | Cause and fix                                                                                                               |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `500` with `BamlValidationError` in the server log | The model did not follow the schema. Send text that matches the route.                                                      |
| `404 Not Found`                                      | Wrong URL.                                                                                                                  |
| `KeyError: 'HOST'` at startup                        | `.env` is missing or incomplete; see [Configure](#configure).                                                              |
| `Request timed out`                                  | The LLM server is not reachable; check`HOST`.                                                                             |
| `Import ... could not be resolved` in VS Code        | The folder is open inside another project's window. Open`BAML_PoC` as its own folder and select `.venv` as interpreter. |
| Port already in use                                    | Set another`PORT` in `.env`.                                                                                            |
